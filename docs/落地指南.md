# 一加 8T(kebab) → Hermes 自托管 Agent 节点 · 落地指南

> 本指南由 6 路并行研究 + 12 条关键事实对抗式复核生成（直接 grep 了 OnePlus 官方 sm8250 内核源码核验）。
> 置信度标注：🟢high / 🟡medium。带 ⚠️ 的是实测坑。

---

## 0. 一句话现实评估

**这套能复刻，但一加 8T 比小米 10 那台难——核心障碍：8T 出厂内核「不能」直接跑 Docker，必须自己编译内核。**

🟢 **已源码证实**：OnePlus 8T(kebab/SM8250) 出厂用的 `vendor/kona-perf_defconfig` 里 `CONFIG_PID_NS` 被**显式关闭**(`# is not set`)，且 `NET_NS / USER_NS / IPC_NS / UTS_NS / CGROUP_PIDS / CGROUP_DEVICE / NF_NAT / NF_NAT_MASQUERADE` 全部缺失。只有 `OVERLAY_FS / BRIDGE / VETH / MEMCG / NAMESPACES / SECCOMP` 已开。
→ 结论：**stock 内核跑不了 Docker/LXC，无解，必须换内核。**
（证据：两个独立内核树 grep 一致 — OnePlusOSS 官方 + PixelExperience fork）

---

## 1. 三条路线对比（必须先选一条）

| | 路线 A: proot 伪 Docker | 路线 B: 自编译内核（真路径）⭐ | 路线 C: postmarketOS |
|---|---|---|---|
| **能跑真 Docker/LXC** | ❌ 不能 | ✅ 能 | ✅ 能 |
| **贴合"图里那套"** | ✗ | ✅ 最贴合 | △ 但非 Android 宿主 |
| **手机还能日用** | ✅ | ✅ | ❌ 不能(modem 废) |
| **难度** | 低 | **高(要编内核)** | 中高(刷 super 分区) |
| **变砖风险** | 无 | 中(先 fastboot boot 验证可控) | 中高 |
| **现成镜像** | 有 | ❌ 无现成 boot.img | 有(但外设全 Untested) |

### 路线 A — proot-distro（不推荐当目标，只作降级）
🟢 **已证实**：Termux + proot-distro 的 Ubuntu 是 **ptrace 拦截 syscall 的用户态模拟**，提供不了 kernel namespaces/cgroups，**即使容器内 root 也跑不了真 Docker/LXC**（官方 README 的 Limitations 章节明文）。
→ 只能跑 podman/OCI 用户态这类"伪容器"。**不满足"6 个 Docker 容器"诉求。**

### 路线 B — 自编译启用容器特性的内核（⭐ 推荐，最贴合需求）
就是图里那套的真实做法：Android 宿主 + root + 自编内核 + Termux/LXC 跑 dockerd。

### 路线 C — postmarketOS（真 mainline Linux）
🟢 **已证实**：kebab 在 pmOS 是 **testing 级**，`Battery/WiFi/Audio/Camera/Bluetooth/Modem/Sensors 全部 Untested`，只有 `Flashing/USB网络/屏幕/触摸 = Works`。
- 优点：mainline 内核自带完整容器支持，跑 Docker 不用补内核。
- 致命点：**modem(通话/短信/蜂窝)在整个 SM8250 OnePlus 系列都不可用**(根因 OnePlus 不释放固件签名密钥)。**手机彻底不能当日用机**，只能当"带屏幕的 ARM Linux 小主机"。
- 姊妹机 OnePlus 8(instantnoodle) 文档成熟度更高(内核6.17，WiFi/蓝牙/GPU 全 Works)，可作可信参照。

## 2. 推荐执行顺序（路线 B）

### Step 1 · 解锁 + 备份（不可跳过）
```bash
# 解 BL（会清空数据，可能影响银行类 App 的 Play Integrity）
fastboot oem unlock
# 关键：先备份 stock boot.img 和 super.img，否则翻车难回退
# （从你当前 OxygenOS 版本对应的官方包提取 boot.img）
```
⚠️ 🟢 **硬约束**：sm8250 内核必须**严格匹配已装 OxygenOS 版本和槽位(A/B, boot_a/boot_b)**，刷错即 bootloop。

### Step 2 · 编译容器内核
以 `OnePlusOSS/android_kernel_oneplus_sm8250`（选匹配你 OxygenOS 的分支，如 `oneplus/SM8250_R_11.0`）为基底，在 `kona-perf_defconfig` 上**补齐**：
```
CONFIG_PID_NS=y          # 出厂被显式关，必补
CONFIG_NET_NS=y
CONFIG_IPC_NS=y
CONFIG_UTS_NS=y
CONFIG_USER_NS=y
CONFIG_POSIX_MQUEUE=y
CONFIG_CGROUP_PIDS=y
CONFIG_CGROUP_DEVICE=y
CONFIG_CGROUP_SCHED=y
CONFIG_NF_NAT=y
CONFIG_NF_NAT_MASQUERADE=y
CONFIG_NETFILTER_XT_MATCH_ADDRTYPE=y
CONFIG_IP_VS=y
CONFIG_VXLAN=y
CONFIG_KEYS=y
# OVERLAY_FS/BRIDGE/VETH/MEMCG 出厂已 =y，保留
```
- ⚠️ 打 `net/netfilter/xt_qtaguid.c` 防 panic 补丁。
- 🟡 `ANDROID_PARANOID_NETWORK`：**8T 不用担心**——复核证实 8T 出厂 Android 11 + 4.19 内核，按 AOSP 政策该选项已被 eBPF 取代、内核里根本不存在（不像老 4.4/4.9 机型）。
- 🟢 编译前后用 moby `contrib/check-config.sh` 跑两遍，直到 `Generally Necessary` 全绿。
- ⚠️ **现成内核陷阱**：网上 `DaniAsh551/docker_kernel_oneplus_sm8250` 这类仓 0 star/0 fork/无 release，**未经社区验证，不能直接信**，要自己编。

### Step 3 · 临时验证再持久化（关键安全动作）
```bash
fastboot boot custom-boot.img   # 先临时 boot，不刷！确认能起、能 check-config 全绿
fastboot flash boot custom-boot.img   # 确认 OK 再真刷
```

### Step 4 · 容器层
🟢 两种都行：
- **Termux 原生 dockerd**：`pkg install root-repo && pkg install docker tini`（docker/containerd/runc 已进 termux-root-packages）
- **LXC 起全 Ubuntu** 再在里面套 Docker：lxc 配置需 `lxc.cgroup.devices.allow=a` + `lxc.mount.auto=cgroup:mixed sys:mixed proc:mixed` + pre-start hook 挂 cgroup/修 DNS。
- ⚠️ **先用 1 个容器验证**（hello-world + 带网络的 nginx，验 overlay/volume/网络），再逐步加到 6 个。

### Step 5~8 · 限充 / 服务 / agent / 穿透 / 监控
见下面各章 + `scripts/` 里的脚本。

## 3. 限充保电（24×7 常插电必做）

🟢 **方案：VR-25 的 ACC（Advanced Charging Controller）**，systemless，Magisk/KernelSU 都行。
```bash
acc -t            # 插着充电器，枚举本机可用充电节点
acc 80 75         # 上限80% 下限75%（服务器建议 70-80%）
acc --set aiapc=false   # 常插电延寿关键：避免高电量 idle
```
⚠️ 🟢 **8T 实测坑**：`battery/input_suspend` 在 ACC 下熄屏几分钟会被系统 wakelock 重新使能，**最终仍充到 100%**。
→ 优先强制 OnePlus 专用节点 `mmi_charging_enable`（新固件 `/sys/class/oplus_chg/battery/mmi_charging_enabled`），它是 hold-at-level 不 ping-pong，对常插电更友好：`acc -ss` 锁定。

❌ **不推荐物理拔电池接 DC**：8T 较新、电池带认证、SD865 仍需电池在位与多点温控，板级注入有 >30% 永久损坏概率，断电不自动重启，不适合无人值守。ACC 限到 ~70% 已能拿到大部分延寿收益。

**散热**：🟢 KonaBess（免重编内核改 GPU 频压表）8T 实测 905MHz@340mv 稳；>920MHz 即使 416mv 仍花屏。CPU 降频需自定义内核。物理上加散热片/小风扇，别放软表面，屏幕常黑。

## 4. 远程访问 / 穿透（CGNAT 后无公网 IP）

🟢 **组合方案**（按受众分工）：
- **Tailscale**（私有）：SSH、管理后台、DB、仪表盘 → 只在 100.x tailnet 内可达，对公网不可见。
  - ⚠️ 手机端必须 `userspace-networking` 模式（内核 iptables 不兼容）；用 Termux:Boot 或 Magisk-Tailscaled 模块开机自启。
  - 移动网多为对称 NAT，WireGuard 直连常失败 → 靠 DERP 中继(走 HTTPS/443)兜底，4G↔WiFi 切换自动重连。
- **Cloudflare Tunnel**（选择性公开）：给别人用的 Web 服务（HA 面板等），无需开端口。
  - 前提：有个域名托管在 Cloudflare。ARM64 装 `cloudflared-linux-arm64.deb`，token 模式跑。
  - 敏感服务叠加免费 Cloudflare Access(Zero Trust) 登录门。❌ 不支持 UDP。
- **frp**（可选）：已有便宜 VPS 且要 UDP/任意 TCP 端口时才上。

🟢 三者统一加 `Restart=on-failure` + `RestartSec=5s` 自动重连。

## 6. Agent 运行时

🟢 在**真 glibc** 的 LXC/Docker Ubuntu 里（区别于裸 Termux 的 bionic libc），主流终端 agent 都能装 ARM64：
| Agent | 安装 | 内存 | 接中转 |
|---|---|---|---|
| **Aider** ⭐省内存 | `pipx install aider-chat` | 最小 | `--openai-api-base` |
| **OpenCode** ⭐贴合"二开内核" | `npm i -g opencode-ai`(有原生 arm64 二进制) | 中 | opencode.json + `@ai-sdk/openai-compatible`(baseURL 以 `/v1` 结尾) |
| Codex CLI | `npm i -g @openai/codex` | 中 | config.toml `[model_providers]` + `wire_api=chat` |
| Claude Code | 官方安装器(linux-arm64) | ⚠️大户 | `ANTHROPIC_BASE_URL` + settings.json env |

⚠️ 🟢 **头号风险：Node 系 agent 内存**。Claude Code 历史有 v1.0.81 级 80-120GB 泄漏；8-12GB 手机无 OOM killer 会直接死锁断电重启。
→ 统一设 `NODE_OPTIONS=--max-old-space-size=2048`，排除重目录，定期重启会话，pin 稳定版关自动更新。

🟢 **会话常驻**：zellij v0.44.3 aarch64-musl(no-web 变体更省内存) + `on_force_close "detach"` + `session_serialization true`；交给 systemd user service(`WantedBy=default.target`) + `loginctl enable-linger`。
⚠️ `ANTHROPIC_BASE_URL` 只在进程启动读一次，改后必须重启 agent（最常见"看似没接上"坑），用 `ps eww <pid>` 验证。

## 7. 风险总清单（按严重度）

1. ⚠️ **bootloop/软砖**：内核必须匹配 OxygenOS 版本+槽位；务必先 `fastboot boot` 临时验证，备份 stock boot.img + super.img。
2. ⚠️ **现成内核陷阱**：单人 0-star 仓未经验证，别直接刷。
3. ⚠️ **内存/OOM**：6 容器 + Node agent 在 8/12G 手机上是真瓶颈，必设 mem_limit + max-old-space-size。
4. ⚠️ **限充失效**：8T input_suspend wakelock 坑，用 mmi/oplus 节点。
5. ⚠️ **cgroup v1 限制**：4.19 下游内核只有 v1，依赖 v2 的新 Docker 特性不可用。
6. ⚠️ **Android FS 加密副作用**：容器 volume 可能显示乱码报 'Required key not available'，无根治法。
7. ⚠️ **Telegram 被墙**：监控告警别只压 Telegram，用 ntfy/Bark。
8. ⚠️ **解 BL 影响银行 App**（Play Integrity/SafetyNet）。
